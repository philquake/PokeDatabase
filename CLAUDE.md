# PokeDatabase — project memory

Django Pokédex app (learning project, built test-first). Single app `pokemon`. Pokémon data
lives in SQLite (`Pokemon`, `PokemonMove`, `PokemonEncounter` models), synced from PokéAPI and
seeded from a JSON file. Owner: philquake.
All development so far happened in 2026 (Aug 6 – Sep 9); see "2026 timeline" below.

## Stack
- Python 3.14 (CI pins 3.14.2), Django 6.0.7, SQLite (all Pokémon data + auth/admin), Bootstrap 5.3.5 (vendored in `assets/static/bootstrap-5.3.5-dist`), vanilla JS (`assets/static/js/main.js`). Fonts are self-hosted (OFL) in `assets/static/fonts/` via `css/fonts.css`: Fredoka (headings, `--font-display`), Inter (text, `--font-body`), DM Mono (dex numbers/footer, `--font-mono`); `base.html` preloads Fredoka + Inter. No Google Fonts requests.
- `requests` for PokéAPI; Selenium for functional tests; `coverage` for CI.
- `requirements.txt` is plain UTF-8 (was UTF-16 until 2026-10-30); also contains unused dev packages (jupyter, matplotlib, pandas, djangorestframework).

## Commands
- First run: `python manage.py migrate && python manage.py import_pokemon_json` (db.sqlite3 is gitignored, so a fresh clone has no data until this runs)
- Run: `python manage.py runserver` → `/` redirects to `/pokemon/`
- Sync from PokéAPI: `python manage.py sync_pokemon [--count N] [--no-update]`
- Move stats (type, physical/special/status, power, accuracy, PP, effect text): `python manage.py sync_moves [--only-known] [--refresh]` (one request per move; `--only-known` = just moves stored Pokémon learn; stored moves are skipped unless `--refresh`). Until it has run, the Moves page is empty and the detail page shows "—" for move stats. Offline alternative: `import_moves_json <file>` (see `pokemon/tests/fixtures/sample_moves.json`).
- Ability effect text: `python manage.py sync_abilities [--only-known] [--refresh]`. Item catalogue: `python manage.py sync_items [--max N] [--refresh]` (~2,000 items, one request each; stored items are skipped so re-running continues). Until run, the Abilities page lists abilities without effect text and the Items page is empty. All three syncs share `_sync_named_resources` in `pokelance_client.py`.
- Unit tests (what CI runs): `coverage run manage.py test pokemon.tests && coverage report --fail-under=80`
- Functional (Selenium, needs a browser): `python manage.py test functional_test`

## Layout
- `PokeDatabase/urls.py` — `admin/`, `""` → RedirectView to `/pokemon/`, `pokemon/` → `pokemon.urls`.
- `PokeDatabase/settings.py` — `STATICFILES_DIRS = [BASE_DIR/'assets'/'static']`, `APP_DIRS=True`, `DEBUG=True`.
- `pokemon/urls.py` routes (names): `home` (`""`), `search`, `pokedex`, `pokemon_detail` (`pokedex/<str:name>/`), `admin_sync_pokemon` (`admin/sync/`), `moves` (Moves list page), `pokemon_moves_fragment` (`pokedex/<name>/moves/<version>/`, HTML fragment), `types` / `type_detail` (`types/<name>/`), `region` / `region_detail` (`region/<name>/`), `abilities` / `ability_detail` (`abilities/<slug>/`), `competitive`, `items`. No placeholder routes remain.
- `pokemon/models.py` — `Pokemon` (unique `pokedex_number` and `name`, `ordering = ["pokedex_number"]`; small grouped data — types, base_stats, abilities, gender, egg_groups, type_effectiveness, evolution_chain — are JSONFields; `region` is set from `generation` in `save()` via `GENERATION_REGIONS`), `PokemonMove` (related_name `moves`) and `PokemonEncounter` (related_name `locations`), both indexed on (pokemon, version). `Ability` (effect text, joined to `Pokemon.abilities` by display name) and `Item` (category, cost, effect, sprite URL) follow the same pattern as `Move`. `Move` holds each move's stats once, unique by display name (same `slug.replace("-", " ").title()` transform as `PokemonMove.name`; no FK — joined by name via `get_move_info`). All registered in `admin.py`.
- `pokemon/management/commands/` — `import_pokemon_json [path]` (load/refresh from a JSON file; default the seed file) and `sync_pokemon`.
- `pokemon/views.py` — views query the DB but pass **fixture-shaped dicts** (via `pokemon_to_dict`) to templates, so templates and tests use `pokemon["name"]` / `pokemon.name` the same as before the DB move.
  - `home`: random hero (with `top_stats` = top 2 base stats; type shown as a coloured dot), 8 random `featured_pokemon`, random `explore_pokemon` name, `pokemon_count`, `move_count` / `ability_count` (distinct). Handles empty data.
  - `pokemon_detail`: case-insensitive name match; context has `pokemon` (incl. `moves`/`locations` lists), `move_generations`, `location_generations`, `growth_rate_label`, `exp_to_100`, `next`/`previous` (nearest stored dex number either side), `evolution_chain` (resolved dicts), `type_defenses` (`defense_cells(types)` from `services/types.py`: 18 cells with the real stacked multiplier — 4×, 2×, 1×, ½×, ¼×, 0× — plus `label` and `state`; drives the Type defenses grid and the hero Weakness chips; stored `type_effectiveness` is no longer used by the template), `type_defense_order` (`TYPE_DEFENSE_ORDER`, kept for tests/legacy), `stat_ranges` (`calculate_stat_range`, Lv100 min/max formula), `learnt_hm`/`learnt_tm` (`group_hm_tm_moves` — PokéAPI only says "machine", HMs split by a hardcoded name set), `locations`. Unknown name → `Http404`; blank name → redirect home with status 400 + message.
  - `moves`: GET `q` (name contains), `type`, `category` (physical/special/status), `sort` (name/type/power/accuracy/pp) + `dir`; 50 per page; invalid filter values are ignored, unknown power/accuracy/PP sort last; empty DB shows how to run `sync_moves`.
  - `pokemon_moves_fragment`: one game's move tables as an HTML fragment (404 for unknown Pokémon or a game with no moves). The detail page renders only the visible game (newest gen, first game) inline; every other game is a `.moves-lazy[data-src]` placeholder that `initLazyMovePanels()` in `main.js` fetches on `shown.bs.tab`. Without this the page was 1.3 MB (≈1,600 rows × ~25 games).
  - `types`: 18 tiles (Pokémon / move counts) + full attacker×defender chart (cells carry multiplier + label). `type_detail`: single-type attack/defend matchups, Pokémon of that type, move count; unknown type → 404. Chart lives in `pokemon/services/types.py` (`TYPE_CHART`, `effectiveness`, `type_matchups`); a test checks it reproduces the PokéAPI matchups stored on every sample Pokémon.
  - `region` / `region_detail`: one region per generation (name from `GENERATION_REGIONS`, games + national-dex range from `GENERATION_GAMES` / `GENERATION_DEX_RANGES` in `versions.py`), Pokémon filtered on `Pokemon.region`.
  - `abilities`: union of abilities held by stored Pokémon and `Ability` rows, with Pokémon counts; GET `q`, `sort=pokemon` + `dir`; 50/page. `ability_detail`: slug ↔ name is `name.lower().replace(" ", "-")` / `.replace("-", " ").title()`; regular vs hidden holders listed separately.
  - `competitive`: ranks every Pokémon (computed in Python) by `stat` (total/hp/attack/defense/special-attack/special-defense/speed), optional `type`; competition ranking (ties share a rank, next rank skips); 50/page.
  - `items`: GET `q`, `category`; 48/page; cost 0 = "Not sold", None = "—".
  - `search`: GET `search` param; exact case-insensitive match → redirect to detail; else `messages.error` + redirect home.
  - `admin_sync_pokemon`: `user_passes_test(_is_staff, login_url="home")` so non-staff go home. POST calls `sync_pokemon_data()`; context `sync_success`, `new_pokemon`, `updated_pokemon`, or `sync_error` on `PokelanceAPIError` (never a 500).
- `pokemon/services/data.py` — dict ↔ model layer (also `save_move_entry`, `move_to_dict`, `get_move_info(names)`, `import_moves_json`): `save_pokemon_entry(entry)` (upsert by dex number; only writes keys present; `moves`/`locations` replace existing rows), `pokemon_to_dict(pokemon, include_related=False)`, `get_pokemon_by_name()`, `import_pokemon_json(path)`, `FIXTURE_PATH` (seed file).
- `pokemon/services/pokelance_client.py` — PokéAPI sync ("Pokelance" is the project's name for it).
  - `_get(url, context)` wraps all HTTP/JSON failures in `PokelanceAPIError` (5s timeout).
  - Per Pokémon fetches: pokemon, species, evolution chain, type damage relations (cached per sync), encounters → `_to_fixture_entry`.
  - Storage seams (mock these in tests): `_existing_numbers()`, `_load_entry(n)`, `_save_entry(entry)`.
  - `sync_pokemon_data(count=5, update_existing=True)`: pass 1 adds up to `count` missing Pokémon, lowest dex number first, up to `NATIONAL_DEX_SIZE` (1025); pass 2 re-fetches every stored Pokémon and saves only drifted/missing fields via `_diff_fields` (ignores `pokedex_number`). Saves each Pokémon as it goes, so a failed sync keeps its progress; returns `{"added": [...], "updated": [...]}`.
  - `GENERATIONS` covers gen I–IX; unknown generation raises.
  - Training card fields (`ev_yield`, `growth_rate`, `held_items`) exist in the models/sync but the 201 seeded Pokémon don't have them yet — the page shows "—" until `sync_pokemon` (with update pass) backfills them from PokéAPI.
  - Known limits: `NATIONAL_DEX_SIZE` is hardcoded (raise it with a new generation); regional forms (PokéAPI ids 10001+) aren't fetched; the admin sync page runs pass 2 inline, which will time out on a big DB — use the command.
- `pokemon/services/versions.py` — `VERSION_GROUPS` table (slug → label, generation; includes both version *groups* used by moves, e.g. `red-blue`, and individual *games* used by wild encounters, e.g. `red`, `the-crown-tundra-sword`), `HM_NAMES`, `GROWTH_RATE_EXP_100`, and the builders `build_move_generations(moves, move_info=None)` (rows gain type/damage_class/power/accuracy/pp/effect from `move_info`; unknown moves keep None) / `build_location_generations(locations)` that return generation → game → sections/rows for the template. Unknown version slugs fall into the newest generation with a title-cased label. Newest generation and first game of each generation are flagged `active`.
- `pokemon/templatetags/pokemon_extras.py` — `get_item` filter (dict lookup by variable key); `has_moves` / `has_encounters` tags are no longer used by the detail template (kept, tested).
- Templates (`pokemon/templates/`): `base.html` (navbar/header/footer, messages shown on every page), `home.html`, `pokedex.html`, `pokemon_detail.html` (258 lines: hero, overview/training, Moves and Location tabs rendered by loops over `move_generations` / `location_generations` via `partials/game_tabs.html`, evolution, breeding; ~300 KB per page vs 3 MB before; nested tab ids are `mv-gen-N`, `mv-<slug>`, `loc-…` — avoid ids starting `panel-` for nested panels because `[id^="panel-"]` has global flex/overflow CSS), `moves.html`, `admin_sync.html`, `404.html`, `partials/evolution_chain.html`, `partials/moves_version.html` (one game's tables), `partials/move_category.html` + `move_sprite.html` (physical/special/status icons via one SVG sprite per page — include the sprite on any page that shows them), `partials/move_legend.html`, `partials/icon.html` (Lucide SVG icons, used instead of emoji), `partials/mon_card.html` (small Pokémon card), `partials/type_chips.html`, `partials/pagination.html`, plus `types.html`, `type_detail.html`, `regions.html`, `region_detail.html`, `abilities.html`, `ability_detail.html`, `competitive.html`, `items.html`.
- CSS: `fonts.css` (@font-face, Latin subsets), `styles.css` (global; design tokens at the top: colours incl. Poké-red `--color-red` / `--color-red-strong`, fonts, type scale `--text-xs … --text-3xl`; the only place `.type-*` colours and the `.mult-*` damage-multiplier box colours are defined), `moves.css` (move chips/icons/tables, shared by the Moves page and the detail Moves tab; fixed column widths ≥768px so sections align, per-row grid on phones), `listing.css` (shared list-page shell: header, filters, tables, tiles, Pokémon cards, plus the Abilities / Competitive / Items page styles), `types.css` (type chart + matchup cards), `pokedex.css`, `pokemon_detail.css` (also holds the Type defenses grid (`.defense-grid` / `.defense-cell`: 3-letter type chip over a `.mult` box, same look as the Types chart) and the previous/next `.pager-card` cards; per-page "extra" CSS block; hero stacks below 900px, no horizontal scroll at 390px).
- Seed file `assets/static/fixtures/pokemon.json` (36 MB; not read at runtime): 205 entries incl. 4 exact duplicates (#7–10), so 201 Pokémon (Bulbasaur … #265, #26–89 missing). Fixture-shaped entry keys (also what `pokemon_to_dict` returns, plus `region`): `pokedex_number, name, image, category, generation, types, base_stats, stat_total, abilities[{name,hidden}], height_m, weight_kg, gender{female_pct,male_pct}|null, egg_groups, catch_rate, base_experience, base_happiness, type_effectiveness{weaknesses,resistances,immunities}, evolution_chain[names], ev_yield{stat:amount}, growth_rate (PokéAPI slug), held_items[names], moves[{name,version,level_learnt,method}], locations[{location,version,method,chance,min_level,max_level}]`. Names are capitalized; base_stats keys are `HP, Attack, Defense, Special Attack, Special Defense, Speed`.

## Design system (Theme A: navy + Pikachu yellow + Poké-red)
- Navy surfaces (`--color-panel`, `--color-bg-*`), yellow for primary actions/focus rings/active states, Poké-red for emphasis (dex-number tags, secondary-button hover, physical-move icon, error flash messages). White text on red must use `--color-red-strong` (5.7:1).
- Use `var(--text-*)` for font sizes (fluid `clamp()` only for page titles) and `var(--font-display|body|mono)`; body `line-height` is 1.6.
- Type chips: `.type-<name>` in `styles.css` sets background **and** label colour (dark ink on light/mid chips, white on dark ones; all ≥4.5:1). Never set `color` on a chip class elsewhere or it overrides the AA label. Dex-page, detail and list pages all use this one set.
- Detail-page navigation: `nav.pokemon-navigation` holds `a.pager-card.previous` / `.next` (`rel="prev|next"`, image + dex number + name, ≥88px tall); the `previous` / `next` classes are what the Selenium tests find. The Type defenses grid deliberately mirrors the Types-page chart (shared `.mult` / `.mult-weak|x2|resist|half|x4|quarter|immune` in `styles.css`; green = takes 2×, amber = ½×, black = 0×; 4× and ¼× are darker shades; neutral cells are blank and dim) and has no key. Cells carry `state-*` classes (never `mult-*`, which would colour the whole cell), link to the Type pages, show the bare number, and say the full type and `N× damage` in `title` / `aria-label`; 9 columns on fine pointers, 6 on phones/touch (≥44px targets).
- Flash messages (`ul.messages`) render under the header (not the footer); `.error` is red, `.info`/`.warning` yellow.
- Adding a font weight/subset: copy the woff2 from the Fontsource npm package into `assets/static/fonts/` and add its `@font-face` to `css/fonts.css` (keep the licence file).

## Gotchas
- Bootstrap's `.navbar-collapse` is `flex: 1 1 100%`; `styles.css` overrides it on desktop so the search box isn't squeezed. Check the navbar at 992–1440px after adding nav links.
- `runserver --noreload` caches templates, so template edits don't show until restart (CSS/JS are fine). Bit me when screenshotting.
- The cloud container's proxy blocks `pokeapi.co`, so `sync_pokemon` / `sync_moves` can't be run there; run them locally.
- `__init__.py` files used to be gitignored, which broke `manage.py test pokemon.tests` on fresh clones (incl. CI). Fixed 2026-10-30 — keep every package's `__init__.py` committed.
- `.gitignore` ignores `db.sqlite3` and personal `outline` notes; run `migrate` locally before using admin.
